---

이 저장소의 `process.md`(프로젝트 진행 상황: 완료된 것 / 남은 것 / 지금 결정 필요한 것)를
관리하는 작업이다. **대화 맥락에 의존하지 말고**, 아래 절차대로 저장소 상태(git, 코드)를
직접 조사해서 작업할 것 — 이 명령은 완전히 새 세션에서도 실행될 수 있다.

## 절차

1. `process.md`가 저장소 루트에 있는지 확인한다.

2. **없으면 새로 만든다:**
   - `git log --reverse --format="%h %ad %s" --date=short`로 전체 커밋 히스토리를
     시간순으로 가져와 타임라인 표로 정리한다.
   - `README.md`를 읽어 프로젝트 한 줄 설명을 작성한다.
   - `config.py`를 읽어 현재 지원하는 설정값을 파악하고, 그중 실제로 등록된 것은
     대화 기록이나 다른 문서 기준으로 판단하되 불확실하면 "확인 필요"로 표시한다.
   - 코드나 다른 문서(README의 "확인 필요" 섹션, `REVIEW_*.md`류, `*_checklist.md`류)에
     남아있는 미해결 항목을 grep/읽기로 찾아 "남은 것(TODO)"에 정리한다.
   - 문서 맨 위에 "마지막 갱신: `<오늘 날짜>` · 커밋 `<현재 HEAD short hash>` 기준"을 명시한다.

3. **이미 있으면 갱신한다:**
   - 파일 상단의 "마지막 갱신: ... 커밋 `<hash>` 기준" 줄에서 마지막 기준 커밋을 읽는다.
   - `git log <그 커밋>..HEAD --reverse --format="%h %ad %s" --date=short`로 그 이후
     새 커밋들을 확인한다.
   - **새 커밋이 없으면**: "이후 새로운 변경 없음, 갱신할 내용이 없습니다"라고 보고하고
     종료한다(파일을 건드리지 않는다).
   - **새 커밋이 있으면**:
     - "완료된 것" 타임라인 표에 새 커밋들을 이어서 추가한다.
     - 새 커밋 내용을 보고 "남은 것(TODO)" 중 해결된 항목이 있으면 체크(`- [x]`) 표시한다
       (삭제하지 말고 완료로 표시하는 걸 우선한다).
     - 새로 생긴 미해결 사항(코드 변경으로 인한 새 TODO, 새로 발견된 이슈 등)이 있으면
       TODO에 추가한다.
     - "지금 당장 결정 필요" 섹션은 사람이 확정했다는 명확한 근거(커밋 메시지, 문서
       수정 등)가 없으면 함부로 지우지 않는다.
     - 상단의 "마지막 갱신" 줄을 현재 날짜·현재 HEAD로 갱신한다.
   - 기존 서술을 함부로 재작성하지 말고, 있는 내용은 최대한 보존하면서 이어붙이는
     방식으로 갱신한다.

4. 실제로 존재하지 않는 파일/함수/설정값을 문서에 적지 않도록, 언급하기 전에
   Read/Grep으로 실제 확인한다 — 확인 없이 추측해서 쓰지 않는다.

5. 작업이 끝나면 `git add process.md && git commit -m "docs: process.md 갱신 (<날짜>)"`로
   커밋하고 push한다(이 저장소는 문서 변경을 확인 절차 없이 바로 커밋·푸시해온 패턴을 따른다).

6. 사용자에게 무엇을 새로 추가/변경했는지 간단히 요약해서 보고한다.
